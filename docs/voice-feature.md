# 语音功能设计文档

MultiSession 插件的语音功能包含两部分：**语音输入**（Speech-to-Text）和**语音播报**（Text-to-Speech）。两者可独立使用，也可通过"语音模式"组合为完整的语音对话体验。

## 语音输入 (Speech-to-Text)

### 技术方案

使用 macOS 原生框架实现，编译为独立的命令行工具：

| 组件 | 文件 | 框架 | 功能 |
|------|------|------|------|
| 录音工具 | `scripts/record.swift` | AVFoundation | 捕获麦克风音频，输出 16kHz/16bit WAV |
| 转写工具 | `scripts/transcribe.swift` | Speech (SFSpeechRecognizer) | 离线语音识别，输出文本到 stdout |

### 录音流程

1. 用户点击 🎤 按钮（或在录音中再次点击停止）
2. Extension 启动 `record` 进程，写入临时 WAV 文件
3. 录音期间 Webview 显示红色状态栏 + 计时器
4. 停止录音后，Extension 启动 `transcribe` 进程处理 WAV 文件
5. 识别结果返回 Webview：
   - **普通模式**：文本插入输入框，用户可编辑后手动发送
   - **语音模式**：文本自动作为用户消息发送到当前会话

### 录音参数

| 参数 | 值 |
|------|-----|
| 采样率 | 16000 Hz |
| 声道 | 单声道 |
| 位深 | 16 bit |
| 格式 | WAV (Linear PCM) |
| 识别语言 | zh-CN（默认，可配置） |
| 识别超时 | 30 秒 |
| 优先模式 | 设备端离线识别 |

### 权限要求

录音需要 macOS 麦克风权限。首次使用时：
- `record.swift` 调用 `AVCaptureDevice.requestAccess(for: .audio)` 触发系统授权弹窗
- 如果被拒绝，Extension 弹出错误提示并提供跳转到"系统设置 → 隐私与安全性 → 麦克风"的链接

## 语音播报 (Text-to-Speech)

### 技术方案

使用 macOS 内置的 `say` 命令实现 TTS，无需额外依赖。

```
say -v Tingting "播报内容"
```

| 参数 | 值 |
|------|-----|
| 语音 | Tingting（中文女声） |
| 最大长度 | 500 字（超出截断） |
| 执行方式 | `child_process.spawn`，非阻塞 |

### 播报触发条件

语音播报**仅在语音模式开启时**自动触发：

1. 语音模式开启（`voiceMode = true`）
2. 收到 `syncLogs` 消息，日志列表有新增
3. 最新一条消息是 `role: 'assistant'`
4. 消息内容与上次播报的不同（去重）

### 播报内容

播报的是 AI 通过 `check_messages(reply="...")` 写入的**回复摘要**，不是 Cursor Composer 中 AI 输出的完整回复。

### 文本预处理

播报前会进行 Markdown 清理（`stripMarkdown`）：

| 处理 | 示例 |
|------|------|
| 移除代码块 | ` ```code``` ` → 空 |
| 移除行内代码 | `` `code` `` → code |
| 移除加粗 | `**text**` → text |
| 移除斜体 | `*text*` → text |
| 移除标题标记 | `## Title` → Title |
| 移除列表标记 | `- item` → item |
| 提取链接文本 | `[text](url)` → text |
| 压缩空行 | 3+ 空行 → 2 空行 |

### 去重机制

通过 `lastSpokenTextRef` 记录最后播报的文本内容，防止同一条消息因 `syncLogs` 多次推送而重复播报。状态读取在 `setLogsMap` 的 updater 函数内完成，确保读到最新的日志列表。

### 停止播报

| 触发方式 | 行为 |
|----------|------|
| 点击"停止播报"按钮 | kill 当前 `say` 进程 |
| 关闭语音模式 | 同步更新 ref + kill 进程 |
| 新消息到达 | 打断当前播报，播放新内容 |

`stopSpeaking` 内部执行 `killall say` 作为兜底，确保没有残留的 `say` 进程。

## 语音模式

语音模式是语音输入和语音播报的组合模式，通过 🔊/🔇 按钮切换。

### 开启时的行为

- 语音输入的识别结果**自动发送**到当前会话（不插入输入框）
- AI 的回复摘要**自动播报**
- 状态栏显示"· 语音模式"标记

### 关闭时的行为

- 语音输入的识别结果**插入输入框**，需手动发送
- 不自动播报
- 如果正在播报中，立即停止

### 状态同步

关闭语音模式时同步更新 `voiceModeRef.current`（不依赖 `useEffect` 的异步更新），避免关闭后仍触发播报的竞态问题。

## UI 组件

### 工具栏按钮

| 按钮 | 图标 | 悬浮提示 | 功能 |
|------|------|----------|------|
| 语音输入 | 🎤 / ⏳ | "语音输入" / "识别中..." / "点击停止录音" | 开始/停止录音 |
| 语音模式 | 🔊 / 🔇 | "开启/关闭语音模式（自动发送+播报）" | 切换语音模式 |

### 状态指示栏

输入框上方的动态状态栏，在以下状态时显示：

| 状态 | 样式 | 文本 | 操作按钮 |
|------|------|------|----------|
| 录音中 | 红色闪烁圆点 | `录音中 MM:SS` | 停止 |
| 识别中 | 黄色闪烁圆点 | `识别中...` | 无 |
| 播报中 | 绿色闪烁圆点 | `播报中...` | 停止播报 |

## 日志

TTS 相关日志输出到 Extension 的 Output Channel（"MultiSession"）：

| 日志 | 含义 |
|------|------|
| `[tts] speaking: "文本..."` | 开始播报（显示前 80 字） |
| `[tts] finished` | 播报正常结束 |
| `[tts] stopped` | 播报被手动停止 |
| `[tts] error: ...` | 播报出错 |

查看方式：Cmd+Shift+U → 下拉选择 "MultiSession"

## 平台限制

- **仅支持 macOS**：`say` 命令和 `SFSpeechRecognizer` 均为 macOS 独有
- **语音选择有限**：中文仅 Tingting 一个语音
- **非流式播报**：等 AI 完整回复后才播报，不支持边生成边播
- **500 字截断**：超长回复只播报前 500 字
- **离线识别依赖系统**：需 macOS 已下载对应语言的离线识别模型
